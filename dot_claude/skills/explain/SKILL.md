# explain

`$ARGUMENTS` の `-t` の値を相手、`-a` を出力形式の指定、残りをトピックとして読む。相手の略記は次の 3 つ。

- `-tn`: そのトピックについて何も知らない人
- `-ti`: その領域を業務で触ったことがある人
- `-tx`: その領域の専門家

どれも無ければ、隣接領域の知識はあるが、そのトピックは初めての人。

相手に合わせて変えるのは、語彙・比喩の題材・説明の粒度・分量の 4 つ。相手が詳しい人なら噛み砕かず、構造と例外を説明する。

## 出力形式

デフォルトはセッション内の返信で説明する。ファイルもアーティファクトも作らない。

- 全体像を 1 文で示してから、部分の説明に入る。
- 図に頼らず言葉で構造を伝える。関係を示すときは `A -> B` のような素の記法か、短い箇条書きを使う。
- 分量は相手の想定に合わせる。網羅より、その相手がつまずく 2〜3 点を厚く書く。

`-a` があるときだけ、その相手が読んで分かる図解を、大きな絵と少ない文字の HTML アーティファクトで作る。書く前に `artifact-design` と `artifact-headings` を読む。

タイトルはトピックをそのまま書く。`-a` に渡されたトピックが既にそれを言っているので、名前らしく言い換えない。詳しくは `artifact-headings` の「タイトル」に従う。
