# Session Summary

現在のClaude Codeセッションの内容を要約したMarkdownファイルを書き出すskill。

単なる「やったことの羅列」ではなく、**後から自分や他人がセッションを再構築できる程度の文脈（why）を残す**ことが目的。

## 引数

| 引数 | 意味 |
|------|------|
| `-d` | 出力先をデフォルト（`~/Documents/vault/claude-logs`）に強制する。ブランチ名による issue ディレクトリへの自動振り分けをスキップする |

引数なしの場合は通常の出力先決定ロジックを使う。

## 出力先

CLAUDE.md の「md ファイル出力先」ルールに従う。`-d` 引数が渡された場合は `~/Documents/vault/claude-logs` を強制使用する。

## ファイル名の決め方

毎回、そのセッション内容に合ったケバブケースのトピックスラッグを考え、日付を末尾につける。

形式: `<kebab-case-topic>-YYYY-MM-DD.md`

良い例:
- `user-settings-page-implementation-2026-05-18.md`
- `login-flow-bug-investigation-2026-05-18.md`
- `data-table-component-refactor-2026-05-18.md`

避けるべき例（汎用的すぎる）:
- `work-2026-05-18.md`
- `session-2026-05-18.md`
- `notes-2026-05-18.md`

トピックスラッグは2〜5語程度で、何のセッションだったか後から見て即座に判別できるようにする。

## ファイル内容のテンプレート

以下のセクション構成で書く。**該当する内容がないセクションは省略する**（無理に埋めると読みづらくなる）。

```markdown
# <セッションタイトル>

- 日時: YYYY-MM-DD
- 作業ディレクトリ: <cwd（あれば）>
- 関連リポジトリ: <repo名 または「なし」>

## 概要

2〜4文で「何を達成したか／何を議論したか」を書く。

## やったこと

時系列または論理順に箇条書き。実際に行った操作・実装・調査を具体的に書く。
ファイルパスは `file:line` 形式で。

## 判断の理由・トレードオフ

なぜその選択をしたか、検討した代替案、却下した理由。
コードや設定からは読み取れない why を残すのがここの主目的。

## ユーザーからの指示・フィードバック

セッション中にユーザーから受けた重要な指示・訂正・好み。
特に「やめて」「こうして」系の指示は引用して残す。

## 未解決事項・次のステップ

TODO、宿題、後で対応すべきこと。
次回セッション再開時の起点になる情報。
```

## 書き出し手順

1. これまでのセッション内容（ユーザー発言・ツール呼び出し・結果を含む全体）を振り返り、上記テンプレートに沿った内容を組み立てる
2. ファイル名用のトピックスラッグを決める
3. **出力先を決定する** — CLAUDE.md の「md ファイル出力先」ルールに従う。`-d` 引数が渡された場合は `~/Documents/vault/claude-logs` を強制使用する
4. 日付はシステムプロンプトの `currentDate` を優先し、なければ `date +%Y-%m-%d` で取得する
5. `mkdir -p <出力先ディレクトリ>` でディレクトリを作成する（既存でも安全）
6. `test -f <出力パス> && echo exists` でファイル存在を確認する
   - 存在する場合: `date +%H%M%S` でローカル時刻サフィックスを取得し、`<topic>-YYYY-MM-DD-HHMMSS.md` にする
7. Write tool で絶対パス指定でファイルを書き出す
8. ユーザーに保存先の絶対パスを1行で報告する（例: `保存しました: ~/Documents/vault/issues/123-add-new-feature/xxx.md`）

## 守ること

- **機密情報を含めない**: APIキー、パスワード、トークン、個人情報など。会話に出てきても要約には書かない
- **why を省かない**: コードや設定からは読み取れない判断の文脈を必ず残す
- **嘘を書かない**: セッション中に実際に発生したことだけ書く。やっていないことを「やったこと」に書かない
- **冗長な前置きを避ける**: ファイル冒頭に「このドキュメントは……」のような自己言及は不要
