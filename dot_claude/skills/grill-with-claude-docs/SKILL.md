# grill-with-claude-docs

Skill ツールで "grilling" を呼ぶ。Docs の操作は docs コネクタの指示に従い、docs skill があれば先に読み込む。

## 記録先

引数に Docs の URL があればその文書に書き足し、無ければ議題を題にした文書を新しく作る。文書は `## 用語` と `## 決定` の 2 節で始める。リポジトリに `GLOSSARY.md` や ADR を作らない。

## 用語

ユーザーの語が曖昧なとき、既に `## 用語` にある定義とずれるとき、コードの実装と食い違うときは、その場で指摘して 1 つの語に決めてもらう。

決まったらすぐ `## 用語` に書き足す。ラウンドの終わりまで溜めない。

```markdown
**注文**: 顧客が商品を買う意思を示したもの。
避ける語: 購入、取引
```

- 定義は 1〜2 文で、それが何かを書く。何をするかは書かない
- このプロジェクトに固有の概念だけを載せる。タイムアウトや例外の種類のような一般的な技術用語は載せない
- 実装の詳細を書かない

## 決定

次の 3 つをすべて満たす決定だけを、ユーザーに確認してから `## 決定` に書く。

1. 後から変えると手間がかかる
2. 文脈を知らない読み手が「なぜこうしたのか」と思う
3. 実際に別の案があり、理由があって選んだ

1 件は見出しと 1〜3 文の段落にし、背景、決めたこと、理由を書く。退けた案は、退けた理由が自明でないときだけ添える。

ユーザーが決めていないことは書かない。grilling の推奨案は、ユーザーが受け入れるまで決定ではない。
