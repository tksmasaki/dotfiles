# アーティファクトのタイトルと見出しと目次

Artifact（claude.ai/code/artifact）で読み物・リファレンス・ガイドを作るときのタイトル・見出し構造・目次。UI・ダッシュボード・ツール系のアーティファクトには適用しない。文章そのものの書き方は `~/.claude/rules/japanese-writing.md` に従う。

## タイトル

### title は扱っている事柄をそのまま書く

`<title>` はギャラリーとタブに出る名前で、読み手が中身を見る前に触れる唯一の 1 行になる。何を扱っているかが、開かなくても分かる形にする。

問題を説明するアーティファクトなら、その問題を書く。何が起きるかが読める形にして、現象に付けた呼び名で置き換えない。

- 良い: `不正な日付で絞り込みが消える`（何が起きるかが読める）
- 悪い: `消える検知日フィルタ`（現象に付けた呼び名で、何が起きるかが分からない）

**「短い名詞句にする」「プロダクトのように名付ける」という一般的な指針を、読み物のアーティファクトに持ち込まない。** その指針は、繰り返し開いて使うツールやアプリを想定している。1 つの事柄を説明する読み物では、名前らしさより、開く前に中身が伝わることを優先する。

title と h1 は同じ判断で書く。両方に同じ文言を置いてよい。

### タイトルでも体言止めのキメ台詞にしない

`~/.claude/rules/japanese-writing.md` の「修辞で強めない」はタイトルにも適用する。短くしようとすると体言止めに寄り、寄った結果として比喩や倒置が入りやすい。**短さのために、何が起きるかを削らない。**

長さで迷ったら、述語まで書いた側を採る。数語に収めることは目的ではない。

## 見出し

### 階層は 4 層で組む

| 層 | 役割 | 書き方 |
| --- | --- | --- |
| eyebrow | セクションの位置づけ | `役割 — その節が答える問い` |
| h1 | 記事全体の主張または読者の問い | 1 文 |
| h2 | その節の結論 | 主張を書く |
| h3 | 節内のブロックの読み方・具体例 | 読み方の指示か、具体そのもの |

表の caption、注意ボックスのラベルも見出しとして扱い、同じ規則を適用する。

### h2 はその節の中身が分かる文にする

見出しだけを拾い読みして記事の論旨が追えることを基準にする。分類ラベル（「概要」「設定方法」「注意点」）は、その節が何を言っているかを伝えないので使わない。

- 良い: `置き場所は配布範囲で決める`
- 悪い: `置き場所について`（分類ラベルで、中身が分からない）

節に結論がなく参照専用（表・チェックリスト）なら、内容を素直に示すだけでよい。例: `早見表`。

**内容を伝えることと、キメ台詞にすることは違う。** 倒置（`〜ではなく〜`）、誇張（`〜しかない`）、比喩（`黙らせる` `無いことになる`）で印象を作らない。カッコつけた見出しが並ぶと、内容より書き手の身振りが目に入る。断定形にこだわらず、`frontmatter で起動できる相手を決める` のように素直な言い方を優先する。

### h3 は 2 通りだけ

1. **読み方の指示** — 直後のブロックをどう読むかを教える。例: `判断は上から順に当てはめる` `表を読むときの注意点`
2. **具体そのもの** — 事例・条件・分岐を、抽象名詞にせずそのまま書く。例: `複数リポジトリで使うならマーケットプレース`

「ここが要点」「補足」のような中身のない見出しは書かない。

### 見出しの形

- 1 見出し 1 主張。句点で 2 文をつなげない。
- 体言止めより、述語まで書く形を優先する。ただし条件節（`〜したいとき`）は述語がなくてよい。
- `text-wrap: balance` を効かせる前提で、折り返しても意味の切れ目が壊れない語順にする。

### eyebrow は軸を 1 つに揃える

セクション間で `役割` の語彙を統一する。「前提 / 判断 1 / 判断 2 / 補足 / まとめ」のように、記事内での位置づけで揃える。コンテンツの型（Reference、Playground）と主題（Accessibility）を混在させると、eyebrow を縦に読んでも構造が見えない。

装飾目的で英語を添えない。h2 と語が重なる eyebrow（`判断 3 — 配り方` の下に `プラグインの配り方`）は、どちらかを削る。

### 番号は順序に意味があるときだけ

`01 / 02 / 03` は、上から順に評価する判断フロー・時系列・手順にだけ使う。並列な選択肢や独立した注意点に振らない。

### 見出しレベルと視覚的な重みを混同しない

強調したいという理由で h2 を使わない。セクション内の要素は h3 にし、必要なら CSS で見せ方を変える。文書のアウトラインが崩れると、スクリーンリーダーの見出しジャンプが壊れる。

## 目次

節が 4 つを超える読み物には目次を付ける。3 つ以下なら、スクロールで全体が見えるので不要。

### 文言は h2 の短縮形にする

目次に h2 の全文を入れない。走査用に短く切り、eyebrow の問い部分と揃える。目次・eyebrow・h2 の 3 者で同じ文言を繰り返さない。短縮の度合いは全項目で揃える。1 項目だけ h2 とほぼ同じ長さ、という状態を作らない。

### 幅で 2 つのモードを出し分ける

- **広い幅**: 左に固定レール（`position: sticky`）。長い資料では、現在地が常に見えることが最大の価値になる。`max-height` と `overflow-y: auto` を付けて、目次自体が画面より長くなっても壊れないようにする。
- **狭い幅**: 開閉式にして畳んでおく。展開したままだと最初の 1 画面を目次が占有する。リンクを押したら自動で閉じる。

`.wrap` を広い幅でだけ grid に切り替え、本文を `.content` でまとめてレールの隣に置く。

### 現在地を示す

IntersectionObserver で現在のセクションに `aria-current="location"` を付ける。`"true"` ではなく `"location"` を使う（文書内の現在位置を表す正確な値）。

- 交差しているセクションが複数あるときは、**文書順で最も上のもの**を選ぶ。コールバックの entry 順に任せると、どれが選ばれるか不定になる。
- 交差が 0 件になったら属性を外す。付けっぱなしにすると、ページ最上部で未読の節が現在地として光る。
- `IntersectionObserver` が無い環境では何もせず、ただのリンク集として成立させる。
- 畳んでいるときは、開閉ボタンに現在のセクション名を出す。畳んだ状態でも現在地が分かる。この表示は `aria-hidden` にして、ボタンのアクセシブル名がスクロールで変化しないようにする。

### 実装で外さない点

- **ページ内遷移はブラウザ本来のフラグメントナビゲーションに任せる。** アーティファクトは iframe 内で描画されるため、`scrollIntoView` が親のスクロールに届かないことがある。`href="#id"` のまま、`preventDefault` しない。
- **移動先の見出しが画面上端に貼り付かないよう、セクションに `scroll-margin-top` を置く。**
- **目次の名前は `nav` の `aria-label` で静的に与える。** `aria-labelledby` で参照した要素が、別の幅で `display: none` になる作りにしない。
- 項目は `ol` + `li` で組む。支援技術が項目数を読み上げられる。

### 番号は付けない方が既定

見出しと同じ判断で、順序に意味があるときだけ番号を振る。項目のラベル（`前提` `判断 1` `補足`）が既に順序と役割を担っているなら、`01 / 02` を重ねない。二重に番号を振ると、順序を持つ項目と持たない項目の区別が消える。
