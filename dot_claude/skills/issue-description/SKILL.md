# issue 本文

新規作成と更新の両方に適用する。リポジトリに issue テンプレートがあれば節の構成はそれに従い、この skill は節の中の書き方を決める。テンプレートの HTML コメントは残さず消す。

## 更新するときは、現在の内容を確認してから重ねる

更新の直前に現在の body を取得して読む（`gh issue view <番号> --json body -q .body` など）。手元の草案や自分が以前生成した内容をそのまま上書きしてはならない。ユーザーや他のメンバーが編集している場合があり、その編集を消してしまう。

変更は現在の内容の上に重ねる。節を作り替える場合も、他者が書いた記述はそのまま残す。表現を整えたい箇所があっても、依頼された変更の範囲を超えて他者の文章を書き直さない。

自分が直前に作成した issue であっても確認する。作成からの経過時間ではなく、間に他者が触れた可能性の有無は分からないという前提で扱う。

## skill 呼び出しで更新するときの手順

1. 対象 issue を決める。引数があればそれを使い、無ければ会話の文脈から特定する。決まらなければユーザーに確認する
2. `gh issue view <番号> --json body -q .body` で現在の body を取得して読む
3. 取得した内容の上に変更を重ねた全文を作り、ファイルに書き出す
4. `gh issue edit <番号> --body-file <ファイル>` で反映する

新規作成でも本文はファイルに書き出し、`gh issue create --title <タイトル> --body-file <ファイル>` で作る。`--body` に長文を直接渡さない。改行やバッククォートがシェルで壊れるのを避けるため。

## 起票の前に既にあるかを探す

**複数の言い回しで検索してから立てる。** 症状の言葉、関係するクラス名、影響する画面名で引く。既にあるのに立てると、議論が 2 箇所に割れる。

見つかったら新しく立てず、その issue にコメントで足す。

## 参照は本文の先頭に置く

親 issue・ユーザストーリー・関連 issue は、最初の見出しより前に 1 行 1 件で並べる。箇条書きにはしない。

- 親 issue は `親 issue: #<番号>` と書く
- ユーザストーリーは `US:` を先頭に置き、タイトルをリンクテキストにしたマークダウンリンクで書く
- 別リポジトリの issue は `<owner>/<repo>#<番号>` で指す

```markdown
US: [ユーザーは通知の送信先を画面から変更できる](https://www.notion.so/...)
親 issue: #1234

## 概要
```

## 節の構成

必要な節だけを置く。使わない節は空で残さず消す。

- `## 概要`: 何が起きているか、何をしたいかを最初に書く。ここだけ読んで起票の理由が分かる状態にする
- `## 根拠`: そう判断した材料を示す。コードの位置は `path/to/file.rb:62-68` の形式、過去の変更は PR 番号かコミットへのリンクで指す
- `## 影響範囲`: 誰に、どの経路で、どの程度影響するか。再現条件が限定的ならその条件も書く
- `## 対応内容`: やることを列挙する。方針が未確定なら見出しを `## 対応方針の案` にして、確定でないことを見出しで示す
- `## 完了条件`: 何を確認できたら閉じてよいかを書く。確認の手段もここに含める
- `## 補足`: 判断に必須ではないが残しておきたい背景

推測と事実を混ぜない。数値には取得元と時点を添える。ユーザーや他メンバーの判断が要る点は、対応内容に紛れ込ませず独立した項目として書く。

## タイトル

1 行で読んで対象と問題が分かる形にする。バグは症状を書き、原因の推測をタイトルに入れない。同じ施策や同じジョブで issue が並ぶ場合は、共通の接頭辞を角括弧で付けて揃える。

## 補足は details に畳む

調査の経過や検証の内訳のうち、対応の判断に必須ではないが残しておきたいものは `<details>` に入れる。計測条件、クエリの全文、突合の結果などが該当する。

summary には「詳細」「補足」ではなく、畳んだ中身の主張を書く。開かなくても何が書いてあるか分かる状態にする。

```markdown
<details>
<summary>計測はローカル DB で 25,000 行 / 回、5 ラウンドの最小値</summary>

...

</details>
```

節の本文には、読み手が対応を判断するために必ず読む必要があるものだけを残す。
