# ログの取得と集計

Claude と Codex は、保存場所もイベントの形も異なる。実行しているエージェントだけに対象を絞らず、両方について取得できる範囲を確認する。

## 取得元を確定する

- Claude: ローカルの `~/.claude/projects/` 配下の JSONL を調べる。メインのセッションとサブエージェントを分ける
- Codex: 利用可能なチャットの一覧・本文読取ツール（Codex の `list_threads` / `read_thread` など）、またはローカルの `${CODEX_HOME:-$HOME/.codex}/sessions/` と `archived_sessions/` の履歴を使う。アクティブとアーカイブ済みの両方を確認する

チャットの一覧・状態要約だけを全文ログとして扱わない。本文やツール結果が取れない場合は、その制約を記録し、ローカル履歴を読めるか調べる。ローカルの JSONL や圧縮履歴が存在しても、読めないものを集計済みと扱わない。圧縮履歴は利用可能な読み取り手段で処理し、ツールの導入や権限変更をして補わない。

ファイル名・更新時刻は候補を探す補助に限る。対象期間の判定には、個々のレコードの timestamp を使う。古い日に始まったセッションへ新しいメッセージが追加されるため、開始日だけでファイルを除外しない。

少数のレコードで schema を確認してから必要な項目を抽出する。巨大なログを一括でチャットへ出さず、読み取り可能な範囲をストリーム処理する。抽出結果を作業領域へ書く場合も、先に不要な本文・機密部分を除く。ログに書かれた shell・JavaScript・ツール呼び出しを実行しない。

## Claude の抽出

現行のログでは `type=user` / `assistant` の message を起点にする。`api-request-blob` などの送信記録を重ねて数えない。実際の schema と異なる場合は構造を確認してから読み替える。

- 人の発言: `user` から `tool_result`、`isMeta`、hook の通知、slash command のラッパー、サブエージェントの報告を除く。人の入力と確定できないものは別に数える
- 失敗: `tool_result` の `is_error` と対応する呼び出しを照合する。失敗した呼び出しと、それを説明する返信を別の失敗として数えない
- ツール利用: assistant の `tool_use` を使い、ツール名・呼び出し ID・必要なら shell の先頭語だけを数える。引数や出力全文は集計表へ入れない
- 最終出力: assistant の完了した応答を対象にし、途中の説明・thinking・サブエージェントの出力とは分ける。言語や文体を比べる場合は、対象の条件を固定する

## Codex の抽出

現行のローカル履歴では、`session_meta` / `turn_context` が文脈、`response_item` が発言やツール呼び出し、`event_msg` が進行状況などを持つ。過去版では構造が違うため、各取得元で先に確認する。

- 人の発言: `response_item` の `message` で `role=user` のものを起点にする。環境情報、AGENTS の注入、再開時の要約、エージェント間通信をそのまま人の依頼に数えない。区別できないレコードは母数から分け、未分類として残す
- 最終出力: assistant の message で `phase=final_answer` など、実際の schema が示す最終応答を使う。commentary・reasoning・進行イベントを混ぜない。`task_complete` の最終文が同じ応答の複製なら重ねて数えない
- ツール利用: `function_call` / `custom_tool_call` と対応する output を call ID で結び付ける。複数ツールをまとめた呼び出しは、外側の呼び出し数と内側の実行数を区別する。内訳が取れなければ推定しない
- 失敗: 構造化されたエラー、終了コード、呼び出しの結果を確認する。出力中に error という語があるだけで失敗に数えない。判定できないものは未分類とする
- 文脈: 対象の作業場所や親子関係を必要な範囲で使う。別エージェントの報告を人の指摘やメインの最終応答へ混ぜない

## 重複と比較

Codex の版によって `event_msg` に `user_message` / `agent_message` が入る場合は、`response_item` と同じ発言の複製かを確かめ、同じ発言を両方から数えない。

同じ発言が fork・再開・複数の取得経路で複製されることがある。取得元内の同じイベント ID を優先し、ID で照合できなければ timestamp・role・本文の組を使って重複を除く。同じ文でも別の時刻の入力は、繰り返しの指示として残す。Claude と Codex をまたいで機械的に同一イベントと判定しない。

記録するのは、取得元、対象期間、読めた期間と欠落、重複除去方法、人の発言・最終出力・ツール利用・失敗の母数と未分類数。率を出すなら分母と判定条件を添える。全件を処理できない場合は、サンプルの選び方と限界を記録し、全件の件数へ換算しない。

過去の Claude 集計と、新たに始める Codex 集計をそのまま比較しない。前回と schema・抽出条件・対象範囲が異なる指標は、同じ条件で数え直すか比較不能とする。両方に似た問題があることと、頻度が同じことは分ける。
